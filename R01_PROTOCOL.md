# C01-R01 protocol

Base revision `3b050e1`. The T02 architecture, generator, vocabulary fitting, split sizes, target, step budget, batch sampling and evaluation cadence come from the original configuration. Training uses a single CPU thread. The experiment crosses three additional corpus seeds with all three original model seeds. Corpus generation uses its own RNG. Forward weights, DFA projection and sampled indices use the original model seed offsets. Record corpus, initial tensor and index-stream fingerprints. Check for document overlap across all splits and corpora, including the historical corpus. [Fixed settings](configs/c01_r01.json)

## Selection and confirmation

1. For each original method, train nine corpus/model pairs for each of three rate multipliers (27 runs per method). Multiply only the fast learning rate or the AdamW learning rate. Select the lowest arithmetic mean of final deployed validation CE over all nine pairs. Resolve exact ties by grid order. Nonfinite or incomplete candidates rank last. Save the selection before evaluating test examples. Every candidate retains its validation results and failure status.
2. On all nine pairs, evaluate default and selected configurations for each original method. At both the original and the selected **spring** rate, also compare the full factorial of anchor consolidation on/off and stiffness plus restoring force on/off. The ablation already supplies the all-off cell. The anchor-off stiffness cell uses its initial anchor as a fixed restoring point. Use fast weights for anchor-off variants and anchors for anchor-on variants. Compare fast and deployed predictions at the same training step. Reuse duplicate settings once. No extra search for the component controls.
3. Reconstruct the historical corpus at the original three rates (one per method) and all three model seeds for position-specific CE and accuracy. Compare with C01 archived scores. This corpus is excluded from selection and pooled new-corpus estimates.
4. Repeat the entire search and confirmation. Compare every numerical learning metric, validation history, selected setting and target status exactly on the same software and hardware. Exclude time, throughput and profiler measurements from exact equality.

## Endpoints and diagnostics

The scientific PASS condition remains final deployed validation accuracy ≥ 66% **and** lower CE than initialization. Preserve FAIL even if an earlier checkpoint hit 66%. Record first observed target step and CPU update time to target on the original 25-step grid. A run that never hits has a missing time to target. Report terminal validation and test CE and accuracy overall and for all five target positions. Position 2 (zero-based) is the first symbol requiring direction and start to be combined.

At the specified checkpoints use a read-only diagnostic on fixed validation position-2 examples. Compute cosine similarity between the DFA batch-mean hidden weight drive and the analytic negative CE gradient for the same hidden weights and examples. Also measure how often flipping only the direction token causes both original and counterfactual next symbols to be predicted correctly. Neither probe changes any weight. Diagnose instability using validation curves, missed or lost targets and nonfinite outcomes. Identical-width AdamW provides a capacity control. Credit and optimizer effects can remain confounded between learners.

Estimate the effect of the coupled stiffness/restoring mechanism by comparing full and anchor-only cells at the same rate, and anchor-only against fast-only. Report paired changes, numbers of improving pairs, and variability across corpora. Three corpus draws limit population inference. Time minibatch selection plus updates, excluding evaluation, probes and setup. Count persistent training-state bytes from allocated tensors. Profile warmed CPU updates separately and report operator time and matrix FLOPs. Scientific learning gates and engineering checks have separate outcomes.
